# Trigger data conventions

This directory contains the data behind `stm32-data-gen/src/trigger.rs`
(which see for how the rules are consumed). `rules.yaml` is GENERATED by
`cargo run --release --bin trigger-rules-build` from the fragments in `raw/`,
concatenated in the order of `raw/manifest.txt`. The first rule whose `match`
regex matches `"<MCU>:<PERIPHERAL>"` wins, so manifest order is
semantically load-bearing — do not reorder casually.
`STATUS.md` records the verification state and provenance of every group.

## Where the data comes from

Each raw fragment's header comments record its provenance:

- `SVD: ...` — extracted from the CMSIS-SVD enumerated values in
  `sources/svd/` (stm32-data-sources submodule) by
  `stm32-data-gen/src/bin/trigger-svd-extract.rs`.
- `RMxxxx` — extracted from the ST reference manual (document number and
  table numbers are cited). RMs are not vendored; the extraction is a
  one-off refresh step and the committed fragment is the source of truth.

When SVD and RM data disagree, the RM wins (SVD enum descriptions are known
to contain copy-paste errors, e.g. timer names that don't exist on the die).

## Signal names

The `signal` is the mux input of the destination peripheral; the numeric
suffix is the register field value (e.g. `EXTSEL[4:0] = 16`).

| Destination | Register field | Signal prefix |
|---|---|---|
| ADC regular | `EXTSEL` | `ADC_EXT_TRG{n}` |
| ADC injected | `JEXTSEL` | `ADC_JEXT_TRG{n}` |
| DAC channel | `TSELx` | `DAC_CHX_TRG{n}` |
| DAC sawtooth increment | `STINCTRIGSELx` | `DAC_INC_CHX_TRG{n}` |
| DFSDM injected | trigger inputs | `DFSDM{m}_JTRG{n}` |
| LPTIM external | trigger inputs | `LPTIM_EXT_TRG{n}` |
| LPTIM input muxes | `IN1/IN2/IC1/IC2` muxes | `LPTIM_{IN1,IN2,IC1,IC2}_MUX{n}` |
| TIM interconnect | internal inputs | `TIMX_{TI1,TI2,TI4,ITR,ETR,BRK,BRK2,SYS_BRK,OCREF_CLR}_IN{n}` |
| SPI/I2C/USART trigger inputs | — | `SPI_TRG{n}`, `I2C_TRG{n}`, `USART_TRG{n}` |

## Source names

Sources are uppercase. Per-family conventions (must match what
embassy-stm32's build.rs expects):

- Timer capture/compare: `TIM{n}_CC{m}` — except F1 and F4, which use
  `TIM{n}_CH{m}` (historical).
- Timer trigger outputs: `TIM{n}_TRGO`, `TIM{n}_TRGO2`.
- HRTIM: `HRTIM_ADC_TRG{n}`, `HRTIM_DAC_TRG{n}`, `HRTIM_DAC_RESET_TRG{n}`,
  `HRTIM_DAC_STEP_TRG{n}`.
- EXTI: `EXTI{n}_TRG` (ADC/DAC), plain `EXTI{n}` (DFSDM, historical).
- Low-power timers: `LPTIM{n}_TRGO`, `LPTIM{n}_CH{n}`, `LPTIM{n}_ETR`.
- Comparators: `COMP{n}_OUT`.
- GPDMA transfer complete: `GPDMA_CH{n}_TC`.
- Misc as they appear in the tables: `RTC_ALRA_TRG`, `TAMP_TRG{n}`,
  `CORTEX_M33_LOCKUP`, `SRAM_PARITY_ERROR`, `FLASH_ECC_ERROR`, `PVD`,
  `LSI`, `LSE`, `HSI16_DIV256`, `ADC4_AWD{n}`, ...

## Rules for extraction

- Skip software triggers (`SWSTART`, `JSWSTART`, `SWTRIG`, `Software`) and
  `Reserved` rows — they are not interconnect sources.
- A table cell like `EXTI line 11 / TIM8_TRGO` becomes TWO entries on the
  same signal index.
- Only emit sources for peripherals that exist on the chips the rule
  matches (e.g. never emit `TIM8_*` for F100/F101, which have no TIM8).
- If a mux input exists in the register field but the RM shows no source
  bonded for the family, omit it (e.g. F410 DAC keeps only its two bonded
  sources).
